# FitTrack: architecture

FitTrack uses Riverpod for state, Firebase Auth and Cloud Firestore for the backend, and a feature-first folder structure.

## Decisions

Each choice favours what one developer can build and maintain in four weeks.

| Area | Choice | Why |
| --- | --- | --- |
| State management | Riverpod (`flutter_riverpod`) | Works without `BuildContext`, catches mistakes at compile time, needs less boilerplate than Bloc, and handles loading and error states with `AsyncValue` |
| Backend | Firebase: Authentication and Cloud Firestore | No server code to write, sign-in is ready-made, live streams and an offline cache are built in, and the free tier covers this app |
| Local persistence | Firestore offline cache | Avoids a second local database and the sync code that comes with it |
| Navigation | `go_router` | Routes are declared in one place and a redirect sends signed-out users to Login |
| Charts | `fl_chart` | Covers the bar and line charts the Progress screen needs |
| Code structure | Feature-first folders with three layers | Each feature's screens, state and data sit together, so one feature can be built and tested at a time |
| Platform | Android first | One target keeps testing manageable; the same code can run on iOS later |

## Layers

A user action travels down through three layers, and data comes back up as streams that rebuild the screen. Only repositories talk to Firebase.

```
+--------------------------------------------------------------+
| Presentation: screens and widgets                            |
| Shows state and sends user actions. No Firebase imports.     |
+--------------------------------------------------------------+
                 |  ref.watch and ref.read
                 v
+--------------------------------------------------------------+
| Application: Riverpod providers and notifiers                |
| Holds screen state, validates input, calls repositories.     |
+--------------------------------------------------------------+
                 |  repository methods
                 v
+--------------------------------------------------------------+
| Data: repositories and models                                |
| One repository per feature. Maps Firestore documents to      |
| Dart models.                                                 |
+--------------------------------------------------------------+
         |  Firebase SDK calls          |
         v                              v
+---------------------------+  +-------------------------------+
| Firebase Authentication   |  | Cloud Firestore               |
| Email and password        |  | Per-user data with offline    |
| sign-in                   |  | cache                         |
+---------------------------+  +-------------------------------+
```

Because screens depend only on providers, a repository can be replaced by a fake one in tests without touching the UI.

## Packages

Seven packages are added on top of the default Flutter project, each at its latest stable version through `flutter pub add`.

| Package | Used for |
| --- | --- |
| `flutter_riverpod` | State management and dependency injection |
| `go_router` | Navigation and the signed-in redirect |
| `firebase_core` | Starts Firebase in the app |
| `firebase_auth` | Email and password sign-in |
| `cloud_firestore` | Database, live streams and offline cache |
| `fl_chart` | Bar and line charts on the Progress screen |
| `intl` | Date and number formatting |

`flutter_lints` and `flutter_test` come with the default project and cover linting and tests.

## Folder structure

Code is grouped by feature; inside a feature it is split into `data`, `application` and `presentation`.

```
lib/
  main.dart                      # starts Firebase and runs the app
  app.dart                       # MaterialApp.router, theme
  firebase_options.dart          # generated by flutterfire configure
  core/
    constants/                   # Firestore paths, default goals
    router/app_router.dart       # all routes and the auth redirect
    theme/app_theme.dart
    utils/                       # bmi.dart, date_utils.dart
    widgets/                     # shared widgets (buttons, cards, empty state)
  features/
    auth/
      data/auth_repository.dart
      application/auth_providers.dart
      presentation/              # login, register, forgot password screens
    home/
      presentation/home_screen.dart
    workouts/
      data/                      # workout.dart, workout_repository.dart
      application/workout_providers.dart
      presentation/              # workouts_screen.dart, workout_form_screen.dart
    progress/
      application/progress_providers.dart
      presentation/progress_screen.dart
    goals/
      presentation/goals_screen.dart
    bmi/
      data/                      # weight_entry.dart, weight_repository.dart
      application/bmi_providers.dart
      presentation/bmi_screen.dart
    water/
      data/                      # water_log.dart, water_repository.dart
      application/water_providers.dart
      presentation/water_screen.dart
    profile/
      data/                      # app_user.dart, user_repository.dart
      application/user_providers.dart
      presentation/profile_screen.dart
test/
  core/utils/bmi_test.dart
  features/                      # mirrors lib/features
```

Goals are fields on the user document, so the Goals screen uses the profile feature's repository and providers.

## Conventions

These rules keep the code consistent across features.

- **Naming:** files in `snake_case`, classes in `PascalCase`, providers end in `Provider`, screens end in `Screen`.
- **Layers:** only files in a `data` folder import Firebase packages. Screens read state from providers and never call a repository directly.
- **Screens:** every screen is a `ConsumerWidget` or `ConsumerStatefulWidget`, one screen per file.
- **Async state:** data from Firestore reaches the UI as `AsyncValue`, and every screen handles its loading, error and empty cases.
- **Models:** immutable classes with `fromMap` and `toMap`; no Firestore types outside the `data` layer.
- **Errors:** repositories throw, notifiers catch, and the screen shows a short message in a `SnackBar`.
- **Forms:** validated with `Form` and `TextFormField` validators before any write.
- **Firestore paths:** collection names are defined once in `core/constants`.
